Public engagement widgets mount once at the public app shell, not inside individual pages, to prevent duplicate chat icons and promotional popups.

Subdirectories may have their own `AGENTS.md` (e.g. `supabase/functions/newsletter/`); read it before changing files there.

CRM pipeline: `configurator_sessions.pipeline_stage` is the single source of truth for the configurator kanban; DB triggers auto-advance it on configurator events but always respect explicit manual changes. Both CRM boards use the shared `crmPipeline` stage catalog and translate external status keys at import boundaries, preventing stages from disappearing. Stage changes sync to the ERP via `sync-to-erp` (`stage_changed`, per-session `erp_webhook_url`). Paginate CRM queries so imported leads are not truncated by the Data API row limit.

The primary ERP CRM route renders the lead board; legacy lead links redirect there, while configurator session tools retain their own route. Contain horizontal board scrolling within the content pane and allow toolbars to wrap so neither CRM expands the page beyond its viewport.

Render active and closed CRM leads through the shared CRMLeadCard presentation component so contact details, next activity and existing lead actions stay consistent without duplicating persistence logic.

Enrich CRM lead cards with paginated, read-only projections of recorded form, chat, email and customer configurator events; never substitute record updated_at for last interaction. Schedule next activities through the existing leads fields, isolated from changes to other lead data.
- Bruno (AI sales & back-office agent): all lead communications live in `crm_messages`; sending and AI suggestions go only through the `bruno-agent` edge function so credentials and stage objectives stay server-side. Email uses shared backend mailbox services with durable outbox states and mailbox leases; SMTP acceptance and IMAP Sent copies are separate, so uncertain sends and APPEND outcomes are never blindly repeated. Mailbox credentials are secret-store-only, TLS is mandatory, logs expose sanitized error codes, and periodic workers consume database-created queued runs. A manual WaSender message pauses Bruno 48h on that lead to avoid overlapping with the human seller.
- Clicking a CRM lead opens the client record (`CRMLeadDetail`: riepilogo, comunicazioni, configuratore) rather than the agent, and the agent's conversation surface is the shared `BrunoPanel` reused inside that record and in the dedicated `/erp/bruno` section, so a lead click always opens the customer while the agent stays reachable from its own entry point.
- Bruno panes use zero-minimum widths, local timeline scrolling and near-bottom following; long text and stale requests must never affect the ERP shell or another customer. BrunoMessage and the local bruno-workspace theme are shared with CRM; timeline filters never change the explicit composer channel. useBrunoMessages pages by (created_at,id), preserves prepend anchors and merges realtime by id; invoker RPCs retain RLS and supply exact summaries instead of downloading global message history.
- Phone calls are owned by the Zapper ERP (recording, transcription, AI analysis); Vesuviano only receives them via the `zapper-call-sync` edge function (x-api-key ZAPPER_SYNC_KEY), filtered to the Vesuviano line, stored as `crm_messages` channel `call` keyed by external_id, so calls are never processed twice.
- Mailbox imports persist physical IMAP identities, then deduplicate CRM projections only with matching participants/content; fetch bounded text parts instead of full attachment MIME to respect hosted resource limits. Independent recent/history cursors prioritize new mail during backfill. Atomic SMTP/APPEND claims and operation deadlines prevent overlapping mailbox leases from duplicating delivery; scheduled callbacks require a private per-run token, never exposed in sales-readable logs.
- ERP mailbox emails use one backend-owned HTML renderer with escaped plain-text bodies and managed signatures; preview uses that same renderer in a sandboxed iframe. Persist rendered text, HTML, signature snapshot and MIME once per outbox operation, so signature edits cannot change retries, Sent copies or CRM deduplication. Signature management is role-checked server-side; transactional/configurator templates stay separate.
- ERP dashboard summaries are read-only projections of existing records with paginated CRM reads, exact count queries and a locally scoped semantic theme; agenda links open the existing CRM customer record through a lead query parameter, without duplicating customer actions or changing operational workflows.
- Commercial offers are isolated from proformas/configurator records; a dedicated edge function validates sales writes and admin settings, snapshots company identity, recalculates totals and exposes only explicitly shared unexpired offers. Preview and PDF use one escaped Vesuviano renderer; catalog reads never mutate prices and customer communications remain owned by Bruno. Offer translation uses server-side streaming structured output with exact item identity and numeric preservation; unavailable catalog prices are never silently inserted as zero and foreign currency requires explicit manual pricing.
- Gennaro's WaSender inbox stays owned by Zapper (single webhook), forwarded through `zapper-whatsapp-sync` for existing leads and deduplicated in `crm_messages`. Bruno sends through the server-only `udc_wasender` gateway connection; never replace Zapper's webhook or automatically repeat uncertain or failed submissions.
- Product prices live in `products` + `product_prices` (one row per price list year × market UK/FR/DE, own currency); exactly one `price_lists` row is active. Saving/activating the active list calls `apply_active_price_list()`, which mirrors UK/FR/DE into legacy A/B/C oven/burner fields so existing configurator, proforma and offer code keeps working until it reads the new tables directly. Customer price = market list − discount (lead `discount_override` replaces `discount_tiers` by `customer_type`).
- Internal agent chats (Bruno via `bruno-chat`, Roberta via `roberta-chat`) share the AgentChat UI, are role-checked and build context server-side (Roberta reuses `_shared/marketing-*` catalog and price policy); threads live in browser localStorage and the active thread/client are URL query params, so client conversations stay separate from agent chats.
- Costs and management data (`product_costs`, `order_cost_entries`, `operating_expenses`) are admin-only via RLS and live outside the catalog; a trigger nulls `products.cost` so sales users can never read costs. The Controllo di gestione page derives margins and P&L in a pure helper module with tests.
